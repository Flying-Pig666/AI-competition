## 摘要

上市公司出事之前,公告和财报里往往早有信号——比如大股东把股票大量质押出去。但这些材料是格式各异的 PDF 甚至扫描件,人工盯不过来;直接问大模型又不靠谱,它会编造数字。我们做了"驼研·信鉴"系统:给它一份公告,它自动提取出"谁质押了多少股"等结构化数据,并且经过"程序验算 + 回原文找证据 + 三个 AI 角色互相挑错"三重把关,保证每个数字可靠;再结合历年财报,用 9 条红旗规则自动判断公司有没有信用风险。在 30 份系统从未见过的真实公告测试中,全部成功处理,校验项通过率 93.5%,提取的字段平均 91.5% 能在原文找到出处;对照实验显示纯规则方法只能从 20% 的公告中完整提取,证明了"AI + 校验"组合的必要性。在风险预警回溯中,系统对康美药业的红色预警比其造假曝光早 1-2 年,对贵州茅台等健康公司零误报。

**关键词**:金融人工智能;信息抽取;大语言模型;多智能体监督;信用风险预警

## 一、引言

### 1.1 我们要解决什么问题

上市公司的大股东缺钱了,常拿手里的股票做抵押借钱,这叫"股权质押"。按规定每次质押都要发公告,写清谁质押、质押多少、什么时候到期。这些信息对银行和投资者很重要——大股东质押比例太高,往往是公司出事的前兆。康美药业 300 亿造假爆雷前,大股东的股票早已几乎全部质押。

但要把这些信息用起来,有三道坎:

1. **公告难读**:几千家公司天天发公告,格式千奇百怪,还有不少是扫描图片,人工提取慢且易错;
2. **数字不能错**:金融数据错一个数就可能误判,要求"零容错";
3. **大模型会编数字**:让 AI 直接读公告,它偶尔会编造看似合理的数字(幻觉),还说不出数字来自哪一页——这在金融场景是致命的。

### 1.2 我们的做法

我们做了一套"提取 → 校验 → 预警"的一体化智能体:AI 负责把公告读成结构化数据(选题一),一套校验机制负责保证数据可靠,可靠的数据再驱动 9 条财务红旗规则做信用风险预警(选题二)。两个选题不是各做各的,而是咬合成一个闭环。

### 1.3 主要贡献

- **三重把关的抗幻觉提取框架**:程序勾稽验算 + 原文逐字溯源 + 多智能体互相监督,让 AI 输出从"看起来对"变成"验算过、有出处";
- **"质疑-裁决"多智能体审查机制**:借鉴 FinSight 的批评循环,设提取员、质疑员、裁决员三个角色,用不同模型互相挑错,共享一份"审查卷宗";
- **"代码算数、AI 说理"的预警引擎**:所有数字由程序计算,9 条红旗规则覆盖业绩变脸、利润含金量、高比例质押等信号,并支持银行业等行业口径豁免;
- **可复现的完整评测**:30 份真实公告盲测、AI/规则双路径对照、康美药业回溯验证,全部数据和日志随代码开放。

## 二、相关工作

**金融信息抽取**方面,CCKS 等竞赛的冠军方案(如 DeepIE)确立了"先分类公告类型、再按模板抽字段"的范式,但它们需要标注数据训练专用模型;我们用大模型做通用提取,不需要训练数据,更适合多题型场景。

**文档解析**方面,MinerU、PaddleOCR 等开源工具能还原文档版面;我们用轻量组合(pypdf/pdfplumber + RapidOCR)实现文本件与扫描件双通道,MinerU 列为升级方向。

**金融多智能体**方面,FinSight(人大高瓴,AFAC2025 冠军)的多智能体协作与"批评循环"(一个 AI 写大纲、另一个 AI 以董事总经理身份只挑毛病、再循环修改)给了我们直接启发;FinRobot 确立了"数字由代码计算、AI 只负责说理"的工程纪律;TradingAgents 用多空辩论提升决策稳健性。我们把"批评循环"从文本写作场景移植到了数据提取场景,并加了程序硬约束兜底。

**财务风险识别**方面,Beneish M-score 等经典模型证明了"利润与现金流背离"等指标的预警价值;我们把这些指标落地为可直接运行的工程规则,每条预警附证据,可人工复核。

## 三、系统总体设计

一份公告从左边进来,可靠的结果和风险报告从右边出去:

```
公告 PDF → ①读懂文件 → ②AI 提取 → ③程序验算 → ④AI 互相监督 → 结构化数据
                                        │(溯源找证据)
财报数据 → ⑤指标计算(纯代码) → ⑥红旗规则预警 → 风险报告
```

六个模块各司其职:解析层负责"读懂文件",提取层负责"把字变成数据",校验层负责"验算和找证据",审查层负责"AI 互相挑错",分析层负责"算指标",预警层负责"下结论"。全程每个动作都写进日志,可回放、可复查。

## 四、实现原理(由浅入深)

### 4.1 读懂公告:文本件与扫描件双通道

公告 PDF 分两种。文字能直接复制的,用程序读取全文并还原表格的行列结构;扫描件本质是一沓图片,先用 OCR 把字认出来,再按每个字在页面上的坐标把表格拼回去。程序自动判断走哪条通道,两种格式最终变成同样的输入。

### 4.2 AI 提取:交作业—批改—订正闭环

把公告全文交给国产大模型(主力 DeepSeek、备用 Kimi),要求它按固定格式输出结构化数据。但大模型第一遍交的"作业"常有小毛病(格式不对、漏记录),所以我们设计了批改闭环:

```
AI 交作业 → 程序检查 → 有错? → 把"错在哪"清单发回去 → AI 订正再交
     ↑____________________(最多 3 轮)____________________|
     3 轮还不行 → 启用规则提取备用方案,流程不中断
```

检查内容包括:证券代码是不是 6 位、股数是不是正整数、比例是不是在 0 到 100 之间、质押公告有没有漏掉记录等。

### 4.3 三道程序安检:格式、验算、找证据

即使作业订正合格,还要过三道安检,这是系统最核心的设计:

**第一道,格式体检**。用强类型校验确认每个字段的类型和格式完全合规。

**第二道,勾稽验算**。会计里的"勾稽"就是数字间的等式关系。公告里的数字天然存在等式,比如"质押后股数 = 质押前 − 本次解除 + 本次新增"。系统自动代入 6 类等式逐一验算,等式不成立就报警。比如三湘印象的公告:`质押前 151,000,000 − 解除 75,000,000 + 新增 51,000,000 = 127,000,000`,与公告披露完全一致。

**第三道,原文溯源**。把提取出的每个数字、日期、人名拿回公告原文逐页搜索(自动尝试"51,000,000"和"51000000"等不同写法)。找到就记下在第几页、原文怎么写的;找不到就明确标记"未溯源,需人工复核"。**编造的字段在这一关无处遁形**。

### 4.4 三个 AI 互相监督:质疑-裁决对抗机制

程序安检能抓"等式对不上"的错误,但还有一类错误等式发现不了——比如数字本身在原文里就存在,只是抄串了行。为此我们借鉴 FinSight 的批评循环,设计了三个 AI 角色互相监督:

| 角色 | 扮演者 | 职责 | 关键约束 |
|---|---|---|---|
| 提取员 | DeepSeek | 读公告、提字段(4.2 节) | 输出格式合规 |
| 质疑员 | Kimi(另一个模型) | 像挑剔的审计师,**只许挑毛病,不许表扬**;每条质疑必须逐字引用原文证据 | 没证据的质疑一律不许提 |
| 裁决员 | DeepSeek | 对每条质疑回原文亲自核对:成立就给出修正值,不成立就驳回 | 不得偏信任何一方,裁决同样要引原文 |

这里有几个讲究:

- **为什么用两个不同模型?** 同一模型自己检查自己,容易"越看越对"(确认偏差);不同模型犯错的模式不一样,互相能照出对方的盲区;
- **质疑员引用的证据可能是编的**,所以裁决员必须亲自回原文核对,而且程序还会最后核验"裁决引用的那段原文是否真实存在"——**AI 的意见也要过规则这道关**;
- **三个 AI 不直接聊天,而是读写同一份"审查卷宗"**:谁提出了什么质疑、裁决结果如何、修正了哪几处,全部记录在一份 JSON + Markdown 卷宗里。卷宗既是智能体之间的共享黑板,也是交付给人看的审查记录。

审查发现错误并修正后,程序会自动重跑一遍勾稽验算和原文溯源,保证最终报告和最终数据一致。

### 4.5 财务分析:代码算数,AI 说理

大模型不擅长算术,所以系统立了条铁律:**所有数字都由程序计算,AI 只做解释**。财务数据通过公开接口双源采集(同花顺 + 新浪财经互相印证),存到本地并记录采集时间和来源,离线也能复现演示。

### 4.6 红旗规则预警:九条规则看风险

在算好的指标上运行 9 条规则,每条对应一类经典风险信号:

| 编号 | 一句话说明 | 举例 |
|---|---|---|
| R1 | 赚了利润没赚到现金 | 净利润为正,经营现金流为负 |
| R2 | 利润靠"外快"撑着 | 非经常性损益占净利润超 30% |
| R3 | 收入降利润反升的怪象 | 两者增速差超 30 个百分点 |
| R4 | 业绩变脸 | 净利润同比暴跌 30%/50% |
| R5 | 连续亏损 | 连续两年净利润为负 |
| R6 | 欠债太多 | 资产负债率超 60%/70% |
| R7 | 利润含金量低 | 每股经营现金流不到每股收益三成 |
| R8 | 大股东质押太多 | 质押占其持股超 50%/70% |
| R9 | 质押集中到期 | 未来半年内有大量质押到期 |

其中 R8、R9 的数据直接来自选题一的公告提取结果——**这是两个选题咬合的关节点**。规则还支持行业豁免:银行天然高杠杆,R1/R6/R7 对银行自动关闭,避免乱报警。最后按触发情况给出"稳健 / 关注 / 高风险"结论,每条预警都附证据和来源。

### 4.7 全程留痕

每处理一份文档,系统都生成流水账日志:读了哪个文件、调了什么工具、给 AI 发了什么、AI 回了什么、每项校验的结论……满足"来源可核验、过程可追溯、结果可复现"。

## 五、实验

### 5.1 实验设置

- **材料一(工程样本)**:三湘印象质押公告(文本版+扫描版)、贵阳银行展期公告,共 3 份;
- **材料二(评测集)**:从巨潮资讯网(证监会指定披露平台)自动采集 2026 年 6-9 月的 30 份真实质押公告,来自 30 家不同公司,系统开发时从未见过——相当于闭卷考试;
- **材料三(预警案例)**:康美药业(造假爆雷,做回溯验证)、贵州茅台(健康白马,测误报)、贵阳银行(测行业豁免)、三湘印象(质押风险联动);
- **模型**:DeepSeek(temperature=0,可复现)+ Kimi(异构审查),均国产;普通电脑 CPU 即可运行。

### 5.2 提取效果:30 份盲测

| 指标 | 结果 |
|---|---|
| 成功处理 | 30/30(100%) |
| 校验全部通过 | 18/30(60%),其余平均只差 1.3 项 |
| 校验项总通过率 | 217/232(93.5%) |
| 字段原文溯源覆盖率 | 平均 91.5%,其中 14 份达 100% |

三份工程样本的校验全部通过(12/12、11/11、12/12),文本版溯源覆盖率 100%。

### 5.3 对照实验:AI + 校验,缺一不可

同一评测集上,对比"纯规则提取"(不用 AI)与"AI 提取":

| 指标 | AI 提取(本系统) | 纯规则提取 |
|---|---|---|
| 校验全部通过 | 18/30 | 6/30 |
| 平均每份提取到记录 | 1.67 条 | 0.40 条 |

纯规则在 30 份里有 24 份一条记录都提不出来——各家公告版式差异太大,写死的规则频频失效。**AI 负责"提得出",校验负责"提得对"**,两者缺一不可。

### 5.4 多智能体审查实验:四个角色合力发现"公告自身印错了"

惠发食品公告的实测过程完整展示了各层机制的协作(详见审查卷宗 `output/603536_惠发食品…review.md`):

1. **提取员**忠实提取公告表格:质押前累计 15,700,000 股、质押后 51,700,000 股;
2. **程序勾稽报警**:15,700,000 − 解除 35,000,000 + 新增 36,000,000 = 16,700,000 ≠ 51,700,000,等式不成立;
3. **质疑员**(Kimi)拿着程序报警线索回原文,提出一种解释:"质押前累计应为 50,700,000(=15,700,000+35,000,000)";
4. **裁决员**(DeepSeek)回原文逐字核对后发现:**公告里根本不存在 50,700,000 这个数字——公告的累计质押表格中印的就是 15,700,000**。裁决"驳回修正,忠于原文";
5. **程序核验兜底**:裁决依据的证据通过真实性核验,系统最终结论"公告数据自相矛盾,挂起转人工复核"。

事后人工核对原文确认:公告文字部分写"解除 35,000,000 股后剩余被质押 15,700,000 股",意味着质押前真实累计应为 50,700,000——**是公告自身的表格口径与文字口径互相矛盾**。我们的系统忠实提取、发现矛盾、拒绝臆造修正、挂起转人工,每个角色都做了正确的事。

同时对三湘印象(已知正确的样本)做误报测试:质疑员零质疑,审查一轮通过——**该挑刺时挑刺,不该挑时不乱挑**。

### 5.5 风险预警回溯:康美药业提前 1-2 年报警

| 时间 | 系统预警 | 证据 | 与爆雷时点关系 |
|---|---|---|---|
| 2017 年报 | R2 利润靠非经常性损益 | 净利润 21.50 亿 vs 扣非 40.28 亿 | 早约 1 年 |
| 2018 年报 | R1 有利润没现金 | 净利润 3.74 亿为正,每股经营现金流 -0.64 元 | 早约 1 年 |
| 2018 年报 | R4 业绩变脸 | 净利润同比 -83% | 早约 1 年 |
| 2019-2020 | R5 巨亏、R6 资不抵债 | 累计亏超 350 亿,负债率 119.5% | 曝光确认 |

系统给出"高风险"结论,红色信号早于造假曝光 1-2 年;贵州茅台(0 红 1 橙,"稳健")与贵阳银行(0 红 0 橙,行业豁免生效)零误报。

### 5.6 错误分析:系统会自己抓错

评测中校验机制主动发现三类问题:①万通发展公告里"股东个体口径"与"一致行动人合并口径"混用,勾稽验算正确识别;②惠发食品公告自身数据矛盾(表格与文字口径不一致),勾稽报警 + 多智能体审查裁决"忠于原文、转人工",详见 5.4 节;③东望时代属"拟签署"预告类公告,本无累计质押表,我们据此把校验规则改进为"不适用"判定——评测反过来帮助系统进化。

## 六、讨论

**局限**:目前覆盖质押/解押/展期三类公告,中标、股权变动类型决赛阶段扩展;扫描件 OCR 噪声仍影响个别字段(溯源机制会显式标记);红旗规则阈值为经验设定,可在标注数据集上寻优;评测集 30 份,人工标注金标准后可算字段级 F1。

**稳健性**:公开数据接口可能失效——数据落盘 + 双源采集应对;AI 服务波动——双模型热备 + 规则兜底,任何一环失效管线都不中断。

## 七、竞赛要求符合性与开源组件

大模型:DeepSeek / Kimi,均为国产;成果形式:结构化 JSON + 校验/预警报告,不依赖对话记录;运行环境:数据落盘、离线可复现、CPU 即可;可追溯:全链路日志 + 字段级溯源页码 + 审查卷宗。

| 组件 | 用途 | 许可证 |
|---|---|---|
| DeepSeek / Kimi API | 提取员/裁决员/质疑员 | 商业 API |
| RapidOCR | 扫描件识别 | Apache-2.0 |
| pypdf / pdfplumber / PyMuPDF | PDF 解析 | BSD / MIT / AGPL |
| akshare | 公开财报采集 | MIT |
| pandas / pydantic | 数据处理/校验 | BSD / MIT |
| Streamlit | 演示网页 | Apache-2.0 |

FinSight(GPL-3.0)仅借鉴多智能体批评循环的架构思想,未使用其代码;FinRobot 的计算纪律、LangExtract 的来源锚定思想同为思路借鉴。业务代码全部自主实现。

## 九、结论

金融数据的价值在于可信。本项目没有停留在"让大模型读公告"的表层,而是用程序验算、原文溯源、多智能体互相监督三重把关,把大模型的能力约束在金融场景要求的严谨性之内;再让可信的数据流动到风险预警,回答"这家公司是否正在积累风险"的真问题。实验表明,系统提取得准(校验通过率 93.5%)、审得出来(程序勾稽与多智能体审查合力发现公告自身的数据矛盾,且对正确样本零误报)、报得够早(康美预警提前 1-2 年)。我们相信,这种"能力 + 纪律"的组合,正是金融人工智能落地的正确姿势。
