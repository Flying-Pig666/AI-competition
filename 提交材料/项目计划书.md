## 摘要

上市公司信用风险暴露之前,质押公告与财务报表中往往早已存在先兆信号,但公告以非标准化 PDF/扫描件发布,人工监控难以规模化,通用大模型直接分析又存在幻觉与不可溯源问题。本文提出"驼研·信鉴"——一个基于公告与财报多源结构化提取的上市公司信用风险预警智能体。系统采用六层架构:(1)数据层融合巨潮公告与双源财报数据并全程留痕;(2)解析层支持文本 PDF 与扫描件双通道;(3)提取层以国产大模型为核心,辅以"校验-重试闭环"保证格式规范;(4)校验层构建"Schema 合规—跨字段勾稽—原文溯源"三层校验体系;(5)分析层遵循"代码算数、模型说理"原则完成指标计算;(6)预警层以红旗规则引擎输出风险结论,并支持行业口径豁免。在三份工程样本上,系统通过全部 12/11/12 项一致性校验,文本件原文溯源覆盖率达 100%;在 30 份未见真实公告的评测集上,系统 100% 跑通,18 份(60%)校验项全部通过、校验项总通过率 93.5%(217/232),平均原文溯源覆盖率 91.5%,校验机制主动发现多例真实提取偏差;消融对照显示 LLM 路径的提取召回显著优于纯规则路径(校验全过率 60% vs 20%,平均每份提取记录 1.67 条 vs 0.40 条)。风险预警回溯实验表明,系统对康美药业造假案的红色预警较曝光时点提前约 1-2 年,而对贵州茅台、贵阳银行等健康标的零误报。

**关键词**:金融人工智能;信息抽取;大语言模型;勾稽校验;来源溯源;信用风险预警

## 一、引言

### 1.1 背景与问题

金融投研工作涉及材料整理、数据提取、财务分析等多个环节。其中两类基础任务长期困扰从业者:

- **公告结构化难**:股权质押、中标、股权变动等公告以非标准化 PDF 乃至扫描件发布,关键字段散落在正文与多级表头的复杂表格中,人工提取慢、易错、不可规模化;
- **财报分析门槛高**:同比/环比核算、非经常性损益识别、利润与现金流背离识别等需要专业训练,而通用大模型直接作答存在数字幻觉、无法溯源,不满足投研严谨性要求。

与此同时,信用风险事件的先兆信号(控股股东高比例质押、利润含金量下降等)恰恰分散在上述两类材料中。**单独做提取或单独做分析,都无法回答"这家公司是否正在积累风险"这一真问题。**

### 1.2 本文贡献

1. **提出"提取-分析-预警"一体化智能体架构**:选题一的结构化提取结果(质押比例、到期压力)直接作为选题二预警引擎的输入,两个任务形成闭环而非拼凑;
2. **设计"校验-重试闭环 + 三层校验"的抗幻觉提取框架**:LLM 输出经 Schema 与业务规则校验,不合格携带问题清单自动重试;提取结果再经勾稽一致性与原文溯源双重核验,未溯源字段显式标记人工复核;
3. **实现"代码算数、模型说理"的财务分析纪律与红旗规则引擎 R1-R9**:所有指标由程序对落盘数据计算,支持银行业等行业口径豁免,质押链式规则直接由提取结果驱动;
4. **完成可复现的实证评估**:含 30 份未见公告的提取评测、LLM/规则双路径消融对照、康美药业回溯验证与健康标的误报检验,全链路日志留痕。

## 二、相关工作

### 2.1 金融文档信息抽取

中文金融信息抽取以 CCKS/SMP 系列竞赛为代表。CCKS 2020 金融篇章级事件抽取冠军方案(DeepIE)确立了"事件类型—主体—要素"三层 Schema 范式,其"先分类公告类型、再按类型抽取要素"的流水线思想与本系统的两阶段 Prompt 设计同构;CCKS 2021 优胜方案进一步引入篇章级与因果关系抽取。与上述依赖标注数据训练专用模型的路线不同,本系统以国产大模型为通用抽取器,无需训练数据即可覆盖质押/中标/股权变动等多类型公告,更适合小样本、多题型的竞赛场景。

### 2.2 文档智能与表格解析

文档解析领域,MinerU(上海 AI Lab)、PaddleOCR/PP-StructureV3、Docling(IBM)等开源工具在复杂版式与表格结构重建上达到很高水平;dots.ocr 等新兴视觉语言模型进一步简化了"检测+识别"流水线。本系统当前采用 pypdf/pdfplumber + RapidOCR 的轻量组合实现文本/扫描双通道解析,并将 MinerU 与 PP-StructureV3 列为决赛阶段的升级路径,以进一步增强合并单元格等复杂表格的解析能力。

### 2.3 金融大模型与多智能体投研系统

FinGLM(SMP2023 方案集)、DISC-FinLLM(复旦)、FinQwen(阿里通义)代表了中文金融大模型的三条路线;FinRobot(AI4Finance)确立了"确定性计算 + LLM 叙述"的工程原则——所有估值与指标计算由代码完成,LLM 仅负责推理与叙述;TradingAgents 的多空辩论机制与决策留痕设计提升了归因稳健性;FinSight(人大高瓴,AFAC2025 冠军)验证了代码驱动多智能体在研报生成上的有效性。本系统吸收上述工程的"计算纪律"与"留痕设计",但聚焦点不同:上述系统面向研报生成或交易决策,本系统面向**公告级结构化提取与信用风险预警的咬合闭环**,并以勾稽校验与原文溯源保证字段级正确性。

### 2.4 财务风险与舞弊识别

经典模型包括 Beneish M-score 与 Piotroski F-score;学术界对 ST 预测、债券违约预测已有成熟研究(如 PrST 模型以 T 期财报预测 T+1/T+2 困境,严格避免前视偏差)。本系统的红旗规则引擎吸收了上述模型的指标思想(利润现金流背离、非经常性损益占比等),并将其落地为可直接运行在公告提取结果与公开财报数据上的工程规则,且每条规则附证据与数据来源,支持人工复核。

## 三、问题定义与系统架构

### 3.1 问题定义

**任务一(公告结构化提取)**:给定公告文档 d(PDF 或扫描件),输出符合预定义 Schema 的结构化记录 R(d) = {doc_meta, records[], cumulative[], risk_items[]},要求字段完整、格式规范、结果一致。

**任务二(信用风险预警)**:给定公司 c 的多年期财务序列 F(c) 与公告提取结果 R(·),输出预警集合 W(c) = {(rule, period, evidence, severity)} 与综合评级 verdict(c) ∈ {稳健, 关注, 高风险}。

### 3.2 六层架构

```
┌──────────────────────────────────────────────────────────────────┐
│                驼研·信鉴 · 信用风险预警智能体                      │
├──────────────────────────────────────────────────────────────────┤
│ 输出层  结构化 JSON │ 一致性校验报告 │ 风险预警报告 │ 溯源证据链     │
│ 预警层  红旗规则引擎 R1-R9 │ 行业口径豁免 │ 综合风险评级            │
│ 分析层  财务指标计算引擎(纯代码:同比/环比/比率,LLM 不碰数字)      │
│ 校验层  ①Schema 合规 ②六类跨字段勾稽 ③原文溯源(逐字段定位页码)    │
```

## 四、方法

### 4.1 多源文档解析

文本层 PDF 由 pypdf 抽取全文、pdfplumber 解析表格并处理多级表头纵向拼接;扫描件经 PyMuPDF 渲染、RapidOCR 识别后,按行框坐标重建表格结构。文本层过少的页面自动判定为扫描页并切换通道,保证两类输入统一进入下游。

### 4.2 校验-重试闭环的结构化提取

LLM 提取并非一次调用,而是闭环(算法 1):

```
算法 1: 校验-重试闭环提取
输入: 公告全文 T,Prompt 模板 P,最大轮数 K=3
1:  messages ← [P(T)]
2:  for k = 1..K do
3:    y_k ← LLM(messages)            # JSON 输出模式
4:    E ← Schema校验(y_k) ∪ 业务规则校验(y_k)
5:    if E = ∅ then return y_k       # 通过:输出
6:    messages ← messages + [y_k, 问题清单(E)]   # 错误回灌
7:  return 异常 → 回退规则提取路径    # 兜底:管线永不中断
```

业务规则校验包括:证券代码 6 位数字、记录类型枚举合法性、股数为正整数、比例值域 [0,100]、质押类公告记录非空等。端点差异(如个别模型仅允许特定 temperature)由客户端自动探测适配。

### 4.3 三层校验体系

**第一层 Schema 合规**:pydantic 强类型校验,杜绝格式错误。

**第二层 跨字段勾稽**(6 类,核心公式):

- 累计勾稽:post_pledge = pre_pledge − release + new(展期不改股数)
- 占其所持勾稽:shares / holding_shares ≈ pct_of_held(相对误差容忍 1%)
- 占总股本勾稽:shares / (holding_shares / holding_pct) ≈ pct_of_total
- 风险提示勾稽:一年内到期股数 == post_pledge;半年内到期 ≤ max(post_pledge)
- 合计行勾稽:合计行 = 明细行加总(比例列为加权)
- 完整性:公告类型 ↔ 记录类型匹配;预告类公告无累计表时勾稽项判定"不适用"而非误报

**第三层 原文溯源**:对每个已提取字段的值生成写法变体(千分位/日期格式/百分比),逐页回原文归一化搜索;命中则记录页码与证据片段,未命中显式标记"未溯源"并提示人工复核。覆盖率 = 命中字段数 / 参与溯源字段总数。

### 4.4 确定性指标计算与双源数据采集

财务数据经 akshare 公开接口双源采集(同花顺财务摘要 + 新浪财务指标),落盘 CSV 并生成采集元数据(来源、时间、行数);同比、环比、比率一律由代码计算,LLM 仅做归因叙述——"数字不出模型口"。

### 4.5 红旗规则引擎(预警层)

| 编号 | 规则 | 触发逻辑(摘要) | 对应竞赛考点 |
|---|---|---|---|
| R1 | 利润与现金流背离 | 净利润>1000万 且每股经营现金流<0 | 利润与现金流背离 |
| R2 | 非经常性损益占比异常 | \|净利润−扣非\|/\|净利润\|>30%(净利润≥5000万) | 非经常性损益 |
| R3 | 营收与利润背离 | 营收降且利润增,增速差>30pp | 异常信号 |
| R4 | 业绩变脸 | 净利润同比降幅>30%(橙)/50%(红) | 业绩变化原因 |
| R5 | 持续亏损 | 连续两年净利润为负 | ST 风险 |
| R6 | 高杠杆 | 资产负债率>60%(橙)/70%(红),银行业豁免 | 偿债能力 |
| R7 | 利润含金量不足 | 每股经营现金流/每股收益<0.3 | 利润质量 |
| R8 | 股东高比例质押 | 质押占其所持>50%(橙)/70%(红),由选题一提取结果驱动 | 咬合点 |
| R9 | 质押到期压力 | 未来半年到期融资余额>0,由提取结果驱动 | 短期偿付 |

综合评级:存在红色规则 → 高风险;橙色 ≥2 → 关注;否则 稳健。银行业等特殊行业的现金流、杠杆口径自动豁免相应规则,避免教科书式误报。

### 4.6 可追溯性设计

每份文档生成 trace.jsonl:文件访问、解析方式、OCR 过程、工具调用、LLM 请求与响应(含 token 用量)、校验结论、溯源结果、结果落盘,逐事件记录;数据采集生成 fetch_meta.json。满足"来源可核验、过程可追溯、结果可复现"。

## 五、实验

### 5.1 实验设置

- **数据集**:(a) 工程样本 3 份(三湘印象质押及解押公告文本版/扫描件版、贵阳银行质押展期公告);(b) 评测集 30 份(2026 年 6-9 月巨潮资讯网真实质押类公告,自动采集、来源 URL 留痕,对系统完全未见);
- **模型**:主力 DeepSeek(temperature=0,保证可复现),备用 Kimi(月之暗面),均国产;
- **对照**:规则提取路径(正则+表格结构解析)作为消融基线;
- **环境**:Windows 11,Python 3,CPU 即可运行,无需 GPU。

### 5.2 主实验:工程样本提取质量

| 测试样本 | 解析方式 | 一致性校验 | 原文溯源覆盖率 |
|---|---|---|---|
| 三湘印象质押及解押公告(文本 PDF) | 文本层 | **12/12 通过** | **100%**(29 项) |
| 贵阳银行质押展期公告(文本 PDF) | 文本层 | **11/11 通过** | **100%**(30 项) |
| 三湘印象公告扫描件(逐页 PNG) | OCR | **12/12 通过** | 86%(未命中项均为 OCR 噪声字段,已显式标记) |

勾稽校验示例(系统自动生成):`黄辉:质押前 151,000,000 − 解除 75,000,000 + 新增 51,000,000 = 127,000,000,与公告披露完全一致`。

### 5.3 评测集主实验(30 份未见公告)

评测集为 2026 年 6-9 月巨潮资讯网真实披露的质押类公告,由 `eval_collect.py` 自动采集并留痕(来源 URL、采集时间),系统开发过程中从未接触该集合。子类型分布:新增质押 15 份、解除质押 7 份、质押及解除质押混合 5 份、质押展期 2 份、其他 1 份。

| 指标 | 结果 |
|---|---|
| 跑通率 | **30/30(100%)**,全部走 LLM 路径,无一份触发兜底 |
| 校验全过率(文档级) | **18/30(60%)**;其余 12 份平均仅差 1.3 项 |
| 校验项总通过率(字段级) | **217/232(93.5%)** |
| 平均原文溯源覆盖率 | **91.5%**(14 份达 100%) |
| 平均每份提取质押记录 | 1.67 条(最多 7 条,天和防务多股东展期) |

代表性样例:天和防务(7 条展期记录,19/20 校验、溯源 100%);坤彩科技(13/13、溯源 100%);万集科技(3 条记录,11/12、溯源 82.4%)。完整逐份结果见 `output/eval/eval_summary.json`。

### 5.4 消融实验:LLM 提取路径 vs 纯规则路径

为回答"大模型在提取环节的增量价值",对同一评测集 30 份公告分别运行 LLM 路径与纯规则路径(正则+表格结构解析,无 LLM),对照结果(`output/eval/compare_llm_vs_rules.json`):

| 指标 | LLM 路径 | 纯规则路径 |
|---|---|---|
| 平均每份提取记录 | **1.67 条** | 0.40 条 |
| 平均每份累计表条目 | **2.40 条** | 1.57 条 |
| 校验全过(文档级) | **18/30(60%)** | 6/30(20%) |

规则路径在 24/30 份公告上提取不到任何质押记录——不同券商/上市公司的公告版式差异极大,正则与表格结构假设频繁失效;LLM 路径则对版式变化稳健。**结论:LLM 提供提取召回的主体能力,校验-重试闭环与三层校验提供正确性保证,二者缺一不可**——这也正是系统将规则路径降级为"兜底与交叉参照"角色的实证依据。

| 2017 年报 | R2 非经常性损益异常 | 净利润 21.50 亿 vs 扣非 40.28 亿,差异率 87% | 早于曝光约 1 年 |
| 2018 年报 | **R1 利润现金流背离** | 净利润 3.74 亿为正,每股经营现金流 -0.64 元 | **早于曝光约 1 年** |
| 2018 年报 | R4 业绩变脸 | 净利润同比 -83% | 早于曝光约 1 年 |
| 2019 年报 | R5 持续亏损 | -46.61 亿 → -310.85 亿 | 曝光确认 |
| 2020 年报 | R6 高杠杆 | 资产负债率 119.5%,资不抵债 | 事后确认 |

**结论:系统的红色信号较造假曝光提前约 1-2 年,回溯验证成立;健康标的零误报,行业豁免机制有效。**

### 5.6 错误分析

评测中校验层主动捕获三类典型偏差,展示系统的自我发现能力:

1. **一致行动人口径差异**(万通发展,3/5):公告中记录表按"股东个体"口径披露占比(100%),累计表按"控股股东及一致行动人合并"口径披露,二者不直接可比;勾稽校验正确识别该差异。后续将引入"口径标注"字段区分个体/合并口径;
2. **累计数字误植**(惠发食品,9/11):LLM 将风险提示段数字误植为质押前累计数(15,700,000 vs 正确值 50,700,000),累计勾稽等式立即失衡报警——证明勾稽校验能抓真问题;
3. **预告类公告误报**(东望时代"拟签署质押合同",修复后 3/3):该类公告无累计质押表,初版校验误报 3 项失败;已修复为"勾稽不适用"判定,展示校验体系的场景适应性迭代。

此外,*ST 春天(溯源 61.1%)等个别低覆盖率样本的未命中字段集中于人名/机构名的 OCR 噪声与单位换算表述差异,均被溯源机制显式标记供人工复核,而非静默放过。

## 六、讨论

**局限性**:① 当前 Schema 覆盖质押/解押/展期三类事件,中标、股权变动类型将在决赛阶段扩展;② 扫描件 OCR 噪声仍影响个别字段(本系统以溯源机制显式标记而非掩盖);③ 红旗规则阈值为经验设定,后续可基于标注数据集做阈值寻优;④ 评测集当前 30 份,人工标注 Gold Standard 后可计算字段级 F1。

**有效性威胁与对策**:公开数据接口存在失效可能(双源采集 + 数据落盘,演示离线可复现);LLM 服务波动(DeepSeek/Kimi 双线路热备 + 规则兜底路径可独立完成提取)。

## 七、竞赛要求符合性声明

- **大语言模型**:DeepSeek(主力)/ Kimi(备用),均为国产大模型,OpenAI 兼容协议调用;
- **成果形式**:结构化数据(JSON)+ 校验/预警报告,不依赖自然语言对话记录;
- **运行环境**:封闭/半封闭——财务数据已落盘,演示不依赖实时网络;
- **可复现**:完整源代码、依赖清单、运行说明随附,关键流程一键运行;
- **可追溯**:全链路 trace.jsonl + 字段级原文溯源页码。

## 十、结论

本文提出的"驼研·信鉴"智能体将公告结构化提取与财务风险预警咬合为一体化闭环:以校验-重试闭环与三层校验体系保证提取结果的字段级可信,以"代码算数"纪律与红旗规则引擎实现可解释的风险预警,并以全程留痕与原文溯源满足金融场景的严谨性要求。初步实验表明系统具备工程可用性与预警有效性。决赛阶段将扩展公告类型覆盖面、完成 Gold Standard 标注与字段级 F1 评测,并提供 Web 演示界面。
